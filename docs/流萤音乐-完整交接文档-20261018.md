### 2. 推荐系统现状（M1 + M2，重要）

**M1 重复修复**（`da69277` + `ab7d93c`，已上线验证）：

- **F9 探索池 8 桶轮转**：`WHERE (unicode(substr(id,1,1)) + unicode(substr(id,2,1))) % 8 = ?` 按 id 哈希分 8 桶、按时间桶轮换取池（`REC_EXPLORE_POOL=240`，桶内 80%）。⚠ 不要改回 `CAST(substr(id,1,8) AS INTEGER)`——hex 含字母时 SQLite 返回 0，**全部歌曲落入桶 0**，轮转失效（线上已实测踩坑）。
- **F1 7 天听过硬排除**：推荐入口排除 7 天内听过（任意进度）的歌曲，与 30 天 ≥50% 黑名单互补。
- **F3 推送去重窗口**：`REC_PUSH_WINDOW` 3h → 24h（长会话中途不再重复推）。
- **F4 参数**：`REC_NOISE 0.6→1.2`、`REC_WEIGHTS.behavior 5.0→4.0`、`explore 0.6→1.0`。

- **S2 健康度过滤**：推荐四路 collected 子查询均加 `AND play_url!=''`（未下载音频不进推荐）。

**M2 天气×时段场景推荐**（`75a3cd3`，已上线验证）：

- 场景源：默认 Open-Meteo（免费无 key），`WEATHER_ENDPOINT` 可换和风（需用户 key）。

- 场景映射（`_scene_for`）：深夜(22-5点)>雨(51-67/80-82/95-99)>雪(71-77/85-86)>酷热(≥30°C)>严寒(≤5°C)>晴天按时段（清晨/午后/傍晚）>阴/雾；无天气数据按时段兜底。共 9 类：雨天治愈/冬日暖歌/夏日清凉/冬日温暖/元气清晨/午后阳光/宁静傍晚/深夜陪伴/阴天舒缓。

### 6. 多码率低码率播放（`1983a11`，已上线，重要）

**背景**：服务器升级 4 核/3.6G 前为 2 核/1.7G，不支持实时转码；采用**懒转码 + 落盘缓存**——首次请求低码率时现场 ffmpeg 转码一次（4 核实测约 12-17s/首），之后直接流缓存文件。

| 项 | 内容 |
|---|---|
| 低码率档 | 96kbps AAC-LC / 44.1kHz / stereo，输出统一 `.m4a`（`-movflags +faststart`） |
| 缓存目录 | `/www/wwwroot/music/files_low/{tid}_96.m4a` |
| 触发 | `GET /api/stream/{id}?br=96`（未就绪同步转码；转码失败自动回退原文件流）；`GET /api/stream-prepare/{id}?br=96`（后台异步转码，立即返回，幂等） |
| 并发控制 | 全局信号量 **并发 2**（4 核/3.6G 升级后适配；2 核时代为 1）+ per-track 锁防同一首重复转码 + 临时文件 `.tmp` 后 `os.replace` 原子落盘 |
| 签名 | 与 /api/stream 同体系（HMAC-SHA256，30 分钟时效）；`br` 为 query 参数不影响签名 |
| 实测 | 转码 23s/首（2 核）→ 17s/首（4 核）；两首并行 16.5s；低码率流 206 total=4022647 vs 原码率 5244542 分离正确；冒烟 153 例无回归 |
| 全量转码 | **未做全量**（用户决策）：懒转码按需生成，空间零负担；如需热门 Top N 预热可随时加 |

### 7. AI 乐评体系（主动评论 + 乐评人形象 + 实时热梗 + 表情包，重要）

2026-10-17 上线，AI 评论从"用户手动触发"升级为完整运营体系（commits：`6e67a0d`→`6c0746a`→`41d7302`→`7646e8e`→`b430dad`）。

**① 主动评论 worker**（`ai.py start_ai_worker`，`main.py` 启动时后台线程，幂等可放心重启）
- 定时（默认 `interval=3600` 秒）自动生成并发布 AI 乐评（默认每轮 `count=2` 条）
- 选歌规则：`offline=0` 且 `play_url` 非空 → 排除近 `skip_days=7` 天已自动评过 + 已有 AI 乐评 ≥ `max_per_track=2` 首
- 发布后写 `comments(is_ai=1)` + 通知歌曲上传者 + 记 `ai_comment_logs`（run_type=auto/manual、status=ok/fail）
- 配置优先级：DB 表 `ai_comment_cfg` > `ai_config.json` > config.py 默认；后台在线改后同步写 `ai_config.json`（权限 600）

**② 乐评人形象**（后台「网站管理」→ AI 评论人形象在线编辑）
- 读 `users` 表 `ai_liuying_comment` 的 name/signature/avatar，评论与通知动态显示
- 头像 multipart 上传存 `files/ai_liuying_comment_avatar.<ext>`（魔数校验）

**③ 实时热梗**（后台可看抓取条数/时间/示例）
- 抓取**百度热搜 + 贴吧热议**双榜聚合为热梗池（TTL 缓存 1h；双源均失败静默降级为纯乐评）
- 按**歌曲信息（歌名 2-4 字 n-gram / 歌手 / 曲风）匹配**相关热梗注入评论 prompt（上限 `HOT_WORDS_MATCH=3`）；匹配不到用全池兜底
- AI 自然融入 1~2 个热梗；线上实测（2026-10-17）当日热搜"沙退湖清"被自然化用进乐评

**④ 随机表情包图片评论**（每条 AI 评论默认 `MEME_PROB_PCT=30%` 概率）
- 源：`meme-api.com/gimme`（Reddit 实时梗图，服务器实测可用，`nsfw` 自动过滤）
- 流程：抓取 JSON 取 `url` → 下载图片（上限 6MB）→ 魔数校验（png/jpg/webp）→ 存 `files/cmt_<32hex>.<ext>`（与用户评论图片同规范）→ `comments.images` JSON 数组 → 经 `/api/comment-image/<name>` 展示（前端图片评论展示已有，无需改）
- 任何失败自动降级为纯文字评论；线上实测 6 条触发 3 条带图（1788×1135 PNG 正常展示）

### 5. 多码率 + 缓存共享（`1983a11`，已推送 GitHub + CI 全绿，重要）

- **码率档决策**：蜂窝 → low（96k）/ Wi-Fi → 原码率 / 离线 → 缓存兜底；播放 URL 优先级：**共享缓存 file://** > 预取签名 URL（码率必须匹配）> 按码率实时签发
- **失败码率升级**：low 卡死/失败 → 升级原码率同曲重载一次 → 仍失败才跳歌（`bitrateUpgraded` 按曲防重）；纵深：`low → high → 跳歌`
- **AudioCache 共享缓存**：`Caches/liuying_audio/{tid}[_96].m4a`，LRU 200；**引擎整曲下载落盘到此 → 原音 AVPlayer 直接 file:// 本地播放（秒开 + 离线可播）**；引擎 prepare 先查缓存（命中免下载）；原音播过的歌不主动落盘（避免无谓写盘）
- **引擎弱网降级**：下载 URL 跟随码率档（蜂窝 low 体积减半）、首字节超时 30s→60s、失败走统一自愈
- **弱网预取联动**：蜂窝预取签名 URL 用 low + 顺带调 `/api/stream-prepare` 预热后端转码（切到该曲时低码率已就绪）

### 5.1 后端懒转码异步化（2026-10-18 线上部署，重要）

**背景**：蜂窝 low 码率首曲若未预热（后台预热 `prewarm_low` 进度约 1150/2425 时），`/api/stream?br=96` 会**同步转码 20-30s** 阻塞首播 → 用户感知"第一首加载明显变长"。

**修复**（`handler.py` 已部署，非仓库提交，线上即时生效）：
- `br=96`/`low` 且未转码 → **后台异步转码**（`transcode_low_async`，同曲锁防重 + 全局信号量并发 2，4 核/3.6G 适配）+ **本次回退原码率流**（响应头 `X-Bitrate-Fallback: 1` 标记），不再阻塞播放
- 转码完成后该曲自动命中 low；客户端现有弱网/缓存逻辑无感（首次可能走原码率流量略高一次）
- **验证**：未转码曲 `br=96` → 秒回 200 + `X-Bitrate-Fallback: 1`；已转码曲 → 直接 low 文件；原码率 → 200 正常
- 后台预热继续（约 3h 后全量就绪，此后蜂窝首曲全部秒开）

### 5.5 发现页"一直加载中"修复（`3651617`+`c0101b6`，已推送 GitHub + CI 全绿 + IPA 交付）

- **根因**：`.task` 串行 `await weather.refresh()` → 定位授权未决（系统弹窗未响应）时 `withCheckedContinuation` **永久挂起** → `load()` 永不执行 → 页面一直停在"加载中…"
- **修复①**：`WeatherContext` 授权/定位等待各加超时 Timer 兜底（授权 3s / 定位 12s；到点自动放行降级"仅时段"），任何调用方不再被永久挂起
- **修复②**：`.task` 内容加载与天气刷新**并行**（async let），天气绝不阻塞内容

### 5.6 播放历史修复 + 前端本地化（`0f9b7e2`+`3595afd`，已推送 GitHub + CI 全绿 + IPA 交付）

- **URL 编码 bug**：`fetchHistory` 用 `appendingPathComponent("history?page=..&size=..")` 拼 query，`?`/`&` 被百分号编码成 `%3F`/`%26` → 后端匹配不到 `/api/history` → 404 → 静默失败 → 列表永远为空（线上已验证：正常 URL 200 / 编码 URL 404）。改 `URLComponents.queryItems`
- **历史本地化**：新增 `LocalPlayHistory`（UserDefaults JSON、**MRU 去重置顶**——同一首重复播放移除旧记录排到第一、上限 100 条、**只存音乐元数据** trackId/title/artist/cover/created，**不存音频文件**）；`HistoryView` 数据源改本地（去掉分页/网络）
- 后端 `recordHistory` 上报**保留**（听歌时长统计 / 推荐行为数据依赖），失败静默不影响播放

### 5.7 我的页听歌时长胶囊（`1b39368`+`a9ffcea`，已推送 GitHub + CI 全绿 + IPA 交付）

- 头像信息区新增 🕒 **累计听歌 X 小时**胶囊（ID 徽标同款白色半透明样式），与"性别·年龄·城市"**同行右侧**

### 5.8 天气卡片修复（`d67f523`+`995a56c`，已推送 GitHub + CI 全绿 + IPA 交付）

- **修复②**：天气不可用不再整卡隐藏，改显示**「仅时段」兜底卡片**（按本地小时：深夜/清晨/上午/中午/下午/傍晚/晚上 + 对应图标），**卡片常驻不消失**

### 6. 逐字歌词"走不完一整句"修复（`e2d70d5`，重要）

**现象**：播放页逐字卡拉OK有时卡在半句走不完；全屏无此问题。

**根因**（线上数据实证 + 前端机制）：
- 线上 267 首 KRC 歌、9409 个逐字行中：**3380 行（35.9%）存在 >300ms 字间空洞**、1973 行（21%）>500ms、574 行（6.1%）>1s、**最大空洞 40890ms**。空洞来源：汽水歌词把句内停顿/间奏算进行内（KRC `<开始ms,持续ms>字` 格式）。
- 播放页 `LyricRowView.filledWidth` 旧版严格按原始字时间戳推进，遇空洞 mask 停在上一字长时间不动 → "走不完一整句"。
- 全屏默认镜台模式有 3D 相机/辉光/粒子持续运动，掩盖了空洞停滞，所以"全屏正常"。

**修复**（`LyricView.swift` `LyricRowView.filledWidth`，一处改动全链路生效）：
- **空洞压缩**：字间间隔 >`gapThreshold=0.6s` 视为停顿（不承载唱词），后续字时间戳整体前移、压缩到保留 `gapKeep=0.15s` 停顿 → 填充连续推进、能走完整句（字序与唱词不变）。
- **字宽估算兜底**：缓存缺失/过期时用 `max(fontSize×1.0, 8)` 估算中文字宽替代 0 → mask 永不封顶半句。
- **验证**：算法级复刻对比（《浪漫诗人demo》2370ms 空洞行：旧版卡 50% 达 2.37s，新版 6300ms 100% 走完；40.9s 极端空洞 500ms 内走完；无空洞歌节奏不变）；本沙箱无 Swift 工具链，**真机编译渲染待验证**。

### 7. 播放页歌词深度分析结论（2026-10-17，供后续排期）

- **P1**：拖动进度条后歌词 ≤0.6s 容差回退滞后（`LyricView.displayTime()` 0.6s 容差 + progress 0.1s 阶梯）

### 6. 播放核心与弱网策略（PlayerManager）

- **ExoPlayer 装配**：`DefaultLoadControl` 弱网工业级参数——minBuffer 5s（快速起播）、maxBuffer 45s（抗抖动）、缓冲 1s 即起播、卡顿后缓冲 3s 再续；`PrioritizeTimeOverSizeThresholds=true`
- **SimpleCache 200MB LRU**（`cacheDir/liuying_audio`）：已缓存歌曲本地直读秒开 + 离线可播；`CacheDataSource` 未缓存走网络并写入缓存，`FLAG_IGNORE_CACHE_ON_ERROR`
- **ForwardingPlayer**：override `seekToPrevious/seekToNext` → 总是切上/下一个 item（通知栏/锁屏按钮不 seekTo(0) 重播）
- **签名 URL 池**：`signedURLPool` 上限 16（LRU 顺序淘汰）；`prefetchAheadCount=4`（当前曲之后预取 4 首）；两阶段预热——先并行签发签名 URL（`warmURLOnly`），再预热元数据（封面 Coil 缓存 → 主色 → 歌词）
- **signedStreamUrl 重试 3 次**（1s/2s/4s 指数退避），失败抛错；`prewarm()` 冷启动预热首曲签名 URL
- **切歌**：高频切歌立即 `pause+clearMediaItems+stop` 清旧流防残留；三态判断（alreadyOnTarget/canAdvance/重建）；切歌时记录上一首播放历史（后端）
- **弱网自愈**：缓冲中 15s 无进展（progress 变化 <0.01）→ 自愈重试；网络错误（ERROR_CODE_IO_NETWORK_*）→ 2s 后自动重试一次（期间切歌/手动恢复取消）；解码器/格式错误 → 500ms 后跳下一首不卡屏
- **队尾续播（汽水式无限流）**：默认模式播到队尾 → `recommend(exclude=已见集合末尾 500)` 追加去重新歌；搜索流走 `Library.loadMore()` 按 keyword 追加；滑到倒数第 2 页触发 `preloadNextBatch` 预加载
- **队列修剪**：>200 首且当前索引 >20 时 drop 前部（保留当前前 20）
- **播放模式**：列表循环/单曲循环/随机；**听歌模式**：默认/我的作品/我的喜欢/新鲜模式（会话 map 缓存，切换保存/恢复；我的作品分页拉全量 ≤20 页）

### 7. 收听结算与行为上报

- 每秒心跳累计收听秒数，**每 30s 上报一次 `listen`**（meta 含 fraction/plays/seconds）；切歌时若 delta≥5s 且 fraction<0.3 额外上报 `skip`
- **双通道**：优先走 WebSocket 上行 `{"type":"behavior","events":[...]}`（已连接则发送并返回 true），未连接回退 HTTP `POST /api/behavior`；`reportPlay` 单独即时上报
- 播放进度刷新只在 `player.currentMediaItem.mediaId == 当前歌 id` 时进行（切歌窗口期不污染进度）

### 8. 会话持久化与登录态

- **PlayerSession**（AppState.kt）：进后台 ON_STOP 保存队列快照（当前前 30 / 后 90）+ 模式 + 播放态，EncryptedSharedPreferences 加密；**5 分钟内重开接着上次下一首**，超 5 分钟清掉进入带随机性的新鲜推荐流；恢复时把队列加入推荐去重集合
- **AppPreloader**（AppState.kt）：启动并行预加载——发现页推荐（`source=discover`，take 10）+ 我的页五路并行（stats/works/likes/comments/unread）；切换账号后 `invalidateMine`
- **AuthManager**：登录态存 EncryptedSharedPreferences（AES256_GCM/SIV）；多账号列表 `saved_accounts`（切换账号先断旧 WS 再恢复）；401 自动清登录态；`profile/update` 响应无 token 时合并保留旧 token；登录后自动启动 WS + 预加载
- **启动放行**（MainActivity/AppRoot）：有登录态 → 等「发现推荐 + 我的页」预加载就绪或 5s 超时；未登录 → 1.2s 后进登录页；切换账号同样走预加载放行
- **AppRouter**（AppState.kt）：selectedTab 默认 1（首页）；`jumpToHome(play, openComment)` 通知点击跨页跳播放 + 打开评论弹窗；上传成功触发我的页刷新

### 9. WebSocket 实时通知（NotificationBus）

- 下行：`{"kind":"notification","notification":{...},"unread":N}`（新通知）与 `{"kind":"event","event":"stats|recommend|track_list|profile|my_tracks",...}`（数据事件）
- 上行：`{"type":"behavior","events":[...]}`（行为实时上报）
- 心跳：OkHttp `pingInterval(25s)` 原生 ping 帧；断线指数退避重连 1s→60s 无上限（onClosed/onFailure 均触发）
- 生命周期：登录后 `startIfNeeded`；切换账号 `stop` 后重建；ON_START `resetAndReconnect` + HTTP 拉未读数；ON_STOP `stop`
- 数据事件驱动：`track_list`→Library 强制重载、`profile`→刷新登录态、`stats`→我的页听歌时长、`recommend`→发现页重拉推荐

### 10. 通知分页与系统通知

- **通知列表分页**：`page/size=30`，列表滚到底部自动 `loadMore`（loadingMore 防并发、hasMore 判停、按 id 去重）；未读数 `NotificationBus.unreadCount` 全局红点
- **PlaybackService 系统通知**：MediaStyle（封面/歌名/作者/上一首/暂停/下一首）；`ACTION_PREV/NEXT/TOGGLE` 前台服务 intent；`ACTION_AUDIO_BECOMING_NOISY` 耳机拔插自动暂停；`startForeground` 立即前台（Android 14 防超时）；封面大图异步加载更新；`onTaskRemoved` 未播放时停服
- **更新弹窗**：启动 1.5s 后 `checkUpdate()`，`forceUpdate=1` 强制不可关，`downloadUrl` 打开浏览器；**公告弹窗**：`showOnce` 按 `SharedPreferences("announcement").shown_id` 去重

### 11. 核心特性

1. **竖滑切歌**：VerticalPager，`settledPage` 稳定后回调切歌（用户滑动与自动切歌隔离）；自动切歌 `animateScrollToPage` 跟随（`isScrollInProgress` 时禁止程序化回跳）
2. **听歌模式**：默认/我的作品/我的喜欢/新鲜模式，会话缓存切换；**无作品隐藏实现**：打开侧边栏时实时调 `myTracks(pageSize=1)` 判 `hasWorks`（iOS 用 AppPreloader.worksTotal 预加载值，实现方式不同、行为一致）
3. **场景音乐 12 宫格**：通勤必听/驾车/起床/深夜 EMO/DJ 模式/助眠模式/动感健身/抖音漫游/洗澡/Chill 放松/快乐时光/电音
4. **封面主色提取**：ColorPalette 整图缩放 1×1 取平均色（等价 iOS CIAreaAverage），播放页/侧边栏背景跟随（`darkened` 压暗：播放页 ×0.35~0.4、侧边栏 ×0.3）
5. **逐字歌词**：KRC/LRC 解析（毫秒级逐字），播放页两句预览卡拉OK白色 mask 填充 + 0.28s easeOutCubic 上滑；全屏歌词自动滚动 + 当前行放大
6. **沉浸式**：`enableEdgeToEdge` 背景延伸到状态栏/导航栏，内容 `statusBarsPadding/navigationBarsPadding` 避让
7. **弱网工业级**：小缓冲快起播 + 大缓冲抗抖 + 200MB LRU 缓存 + 15s 卡死自愈 + 网络错误重试 + 解码错误跳歌（详见第 6 节）
8. **系统均衡器 EQ**（音效）：`Equalizer(0, audioSessionId)` 5 band 近似实现——3D 立体/360 环绕/复古/现场/流行/摇滚（预设毫贝增益表），「原音」关闭均衡器；⚠ 与 iOS 不同：iOS 引擎音效是下载音频文件 + AVAudioEngine 混音，Android 是系统均衡器近似

## 十一、交接注意事项

1. **线上代码与仓库当前一致**（2026-10-17 实测后端 md5 对齐 `server/{handler,media,database,config,main}.py`；最新 `1983a11` 含后端多码率改动，**线上 media.py/handler.py 已单独部署**，与仓库一致）。修改代码后：push main → 上传对应文件 → 重启对应服务。
2. **`source.js` 不入库**：长青音源脚本是外部文件且混淆加密，全新部署需手动放入 `source-bridge/`；覆盖升级会自动从备份恢复。线上保留 `source.js.bak_v120_20261014` 与 `source.js.new`。
3. **管理后台真实密码是 `<见服务器 admin_pwd 文件>`**（`/www/wwwroot/music/admin_pwd` 文件内容）；旧文档里的 `liuying-admin-8f3a` 不生效。
4. **8787 端口是同机 wish 项目的服务**，与本项目无关，勿误操作；本项目后端是 8788，对外 API 走 `/music/api`。
5. **GM 兜底音源依赖 `music-dl`（18080）**，非 systemd 托管，重启需手动 nohup。
6. **`.sign_secret` 勿删**：删除会导致已分享短链失效、音频签名流无法校验。
7. **探索桶哈希勿改回 CAST 写法**：`unicode(substr(id,1,1))+unicode(substr(id,2,1)) % 8` 是 M1 踩坑后的正确实现；CAST 对 hex 全归桶 0。
8. **采集歌健康度**：`play_url` 为空的采集歌不进推荐（S2）；`download_collected.py` 负责回填。`collected_tracks.play_count` 由 `/api/play` 同步自增（S1，热度路覆盖采集歌）。
